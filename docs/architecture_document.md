# Basana 项目架构文档

## 1. 项目概述
Basana是一个专注于加密货币的Python异步事件驱动算法交易框架，采用Apache 2.0许可证。核心设计理念是基于事件驱动的异步架构，支持回测和实时交易两种模式。

## 2. 核心架构组件

### 2.1 事件系统 (Event System)
**核心文件**: `basana/core/event.py`
- **Event基类**: 所有事件的基类，包含时间戳
- **EventSource抽象基类**: 事件源抽象，定义事件生成接口
- **Producer生产者模式**: 负责生成和推送事件
- **FifoQueueEventSource**: 基于队列的先进先出事件源实现
- **事件流机制**: 
  - 事件源 → 事件队列 → 事件分发器 → 事件处理器
  - 回测模式：基于历史数据的离散事件模拟
  - 实时模式：基于WebSocket的连续事件流

### 2.2 事件分发器 (Event Dispatcher)
**核心文件**: `basana/core/dispatcher.py`
- **EventDispatcher抽象基类**: 定义事件分发接口
- **BacktestingDispatcher**: 回测分发器，支持时间推进和事件调度
- **RealtimeDispatcher**: 实时分发器，基于asyncio的实时事件处理
- **EventMultiplexer**: 事件多路复用器，合并多个事件源
- **SchedulerQueue**: 调度队列，管理待处理事件

### 2.3 回测引擎 (Backtesting Engine)
**核心文件**: `basana/backtesting/exchange.py`
- **Exchange类**: 模拟真实交易所行为
- 支持订单类型: 市价单、限价单、止损单、止损限价单
- 集成组件: 账户余额、费用策略、流动性策略、借贷管理
- **ExchangeContext**: 交易所上下文，提供统一的服务访问

### 2.4 订单管理系统
**核心文件**: `basana/backtesting/order_mgr.py`
- **OrderManager**: 管理订单完整生命周期
- 功能包括: 订单接受、余额冻结、订单处理、费用计算
- 支持自动借贷和还款机制
- 订单状态跟踪和事件推送

### 2.5 WebSocket实时数据流
**核心文件**: `basana/core/websockets.py`
- **WebSocketClient基类**: 通道化WebSocket客户端
- **ChannelEventSource**: 从WebSocket消息生成事件的事件源
- 特性: 自动重连、心跳机制、消息处理循环
- 支持多通道订阅和管理

### 2.6 配置管理系统
**核心文件**: `basana/core/config.py`
- **分层配置**: 支持默认配置、环境配置、用户覆盖
- **统一接口**: `get_config_value`函数提供一致的配置访问
- **交易所特定配置**: 如Binance的API端点、超时设置

### 2.7 错误处理策略
**核心文件**: `basana/core/errors.py`, `basana/backtesting/errors.py`
- **异常层次**: 从基类Error派生的特定错误类型
- **回测特定错误**: NotEnoughBalance、NotFound等
- **错误处理机制**: 结构化日志记录、异常传播

## 3. 关键架构机制

### 3.1 事件流机制
**回测模式时序处理**:
1. 历史数据加载到事件源
2. BacktestingDispatcher按时间顺序推进
3. 订单在对应时间点的K线事件中处理
4. 模拟真实市场条件下的订单执行

**实时模式时序处理**:
1. WebSocket连接建立和数据流订阅
2. RealtimeDispatcher实时处理传入事件
3. 立即响应市场数据变化
4. 支持高频数据流处理

### 3.2 配置管理实现
- **配置路径**: 支持点分隔的配置路径（如`binance.spot.timeout`）
- **覆盖机制**: 用户配置优先于默认配置
- **类型安全**: 自动类型转换和验证

### 3.3 错误处理策略
- **网络错误**: WebSocket重连机制，指数退避策略
- **订单失败**: 余额不足检查，订单状态跟踪
- **数据不一致**: 数据验证和异常处理
- **重试机制**: 关键操作的自动重试逻辑

### 3.4 扩展性设计
**添加新交易所**:
1. 实现交易所特定的WebSocketClient
2. 定义交易对信息和配置
3. 实现订单管理和账户接口
4. 集成到事件分发系统

**事件类型扩展**:
- 继承Event基类定义新事件类型
- 实现对应的事件源和处理器

**订单类型扩展**:
- 继承Order基类定义新订单类型
- 实现订单特定的执行逻辑

### 3.5 性能考虑
- **异步架构**: 全链路asyncio支持，避免阻塞
- **内存管理**: 使用生成器和迭代器处理大数据集
- **连接管理**: WebSocket连接池和会话复用
- **限流机制**: TokenBucketLimiter控制API调用频率

### 3.6 数据流设计
**市场数据流**:
- WebSocket实时数据 → ChannelEventSource → 事件处理器
- CSV文件数据 → CSVEventSource → 回测引擎

**订单数据流**:
- 订单创建 → OrderManager → 余额冻结 → 订单执行 → 状态更新

**账户数据流**:
- 余额查询 → AccountBalances → 余额更新事件
- 借贷管理 → LoanManager → 利息计算

## 5. 开发工具和依赖管理

### 5.1 项目构建和依赖管理
**核心文件**: `pyproject.toml`, `poetry.lock`, `DEVELOPERS.md`

- **构建工具**: 使用Poetry进行依赖管理和包构建
- **Python版本**: 要求Python 3.9或更高版本
- **核心依赖**:
  - `aiohttp`: 异步HTTP客户端/服务器，支持WebSocket
  - `python-dateutil`: 日期时间处理工具
- **可选依赖**:
  - `plotly` + `kaleido`: 图表生成（charts额外功能）
  - `pandas`, `statsmodels`: 数据分析和统计建模
  - `talipp`: 技术指标计算
  - `textual`: 终端用户界面

### 5.2 开发工作流
- **虚拟环境**: 使用Poetry管理隔离环境
- **静态检查**: 
  - `mypy`: 类型检查
  - `ruff`: 代码格式化和linting
- **测试框架**: 
  - `pytest`: 测试运行器
  - `pytest-cov`: 代码覆盖率
  - `pytest-mock`: 模拟测试
- **文档构建**: 使用Sphinx和ReadTheDocs主题

## 8. 核心设计模式和架构原则

### 8.1 主要设计模式
- **观察者模式**: 事件源和事件处理器的解耦
- **策略模式**: 不同的交易策略实现
- **工厂模式**: 事件源和分发器的创建
- **装饰器模式**: 配置管理和错误处理
- **状态模式**: 订单状态管理

### 8.2 架构原则
- **单一职责**: 每个类有明确的单一职责
- **开闭原则**: 通过继承和接口支持扩展
- **依赖倒置**: 依赖抽象而非具体实现
- **接口隔离**: 细粒度的接口设计
- **异步优先**: 全链路异步非阻塞设计
